# Technical Specification — Tasks REST API

## Overview

The task manager gains a server-side backend. A Node.js + Express application exposes a JSON REST API backed by PostgreSQL for **tasks** and **projects**, and serves the existing static frontend (`index.html`, `app.js`, `vendor/`) so the app runs as a full stack. The frontend is rewired to call the API instead of `localStorage`; rendering, drag-and-drop, filtering, and validation behavior are unchanged.

## Data Model

The database mirrors the existing client-side models. Columns are snake_case; the API returns and accepts camelCase JSON to match the frontend.

### Task

```
Task {
  id:        string    (UUID v4, generated by the client)
  title:     string    (required, max 255 chars)
  status:    string    ("prioritize" | "in-progress" | "completed", default: "prioritize")
  createdAt: string    (ISO-8601 timestamp, set by the database)
  startDate: string    (YYYY-MM-DD, optional)
  color:     string    (Bootstrap text-bg-* class, auto-assigned by the server, unique among tasks)
  projectId: string    (nullable, FK -> projects.id; null = ungrouped)
}
```

`tasks` table:

```sql
id          TEXT PRIMARY KEY,
title       TEXT NOT NULL,
status      TEXT NOT NULL DEFAULT 'prioritize',
created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
start_date  DATE,
color       TEXT NOT NULL DEFAULT 'light',
project_id  TEXT REFERENCES projects(id) ON DELETE SET NULL
```

### Project

```
Project {
  id:          string    (UUID v4, generated by the client)
  name:        string    (required, max 255 chars, unique)
  icon:        string    (palette/icon key, default: "default")
  startDate:   string    (YYYY-MM-DD, optional)
  endDate:     string    (YYYY-MM-DD, optional)
  description: string    (optional)
  createdAt:   string    (ISO-8601 timestamp, set by the database)
}
```

`projects` table:

```sql
id           TEXT PRIMARY KEY,
name         TEXT NOT NULL UNIQUE,
icon         TEXT NOT NULL DEFAULT 'default',
start_date   DATE,
end_date     DATE,
description  TEXT,
created_at   TIMESTAMPTZ NOT NULL DEFAULT now()
```

On first boot the three default projects (**Office Project**, **Personal Project**, **Daily Study**) are seeded if the table is empty.

## API

Base URL: `/api`. All endpoints accept and return JSON (`Content-Type: application/json`).

### Tasks

| Method | Path              | Description                                      |
| ------ | ----------------- | ------------------------------------------------ |
| GET    | `/api/tasks`      | List all tasks, ordered by creation time         |
| POST   | `/api/tasks`      | Create a task; returns `201` + created task      |
| GET    | `/api/tasks/:id`  | Read one task; `404` if missing                  |
| PUT    | `/api/tasks/:id`  | Update task fields (partial merge); returns `200` + updated task |
| DELETE | `/api/tasks/:id`  | Delete a task; returns `204`                     |

`POST` body: `{ title, status?, startDate?, color?, projectId? }` (only `title` required; `color` auto-assigned when omitted).
`PUT` body: any subset of `{ title, status, startDate?, color?, projectId? }`; omitted fields keep their current values.

### Projects

| Method | Path                 | Description                                               |
| ------ | -------------------- | --------------------------------------------------------- |
| GET    | `/api/projects`      | List all projects, ordered by creation time               |
| POST   | `/api/projects`      | Create a project; returns `201` + created project         |
| GET    | `/api/projects/:id`  | Read one project; `404` if missing                        |
| PUT    | `/api/projects/:id`  | Replace project fields; returns `200` + updated project   |
| DELETE | `/api/projects/:id`  | Delete a project; returns `204`; tasks get `projectId = null` |

## Validation

- `title` / `name`: required, non-empty after trimming, max 255 chars → `400`.
- `status`: must be one of `prioritize`, `in-progress`, `completed` → `400`.
- `startDate` / `endDate`: optional; must be valid `YYYY-MM-DD` → `400`.
- `endDate` must not be before `startDate` → `400`.
- `projectId`: must reference an existing project → `400` (FK violation mapped to `400`).
- Duplicate project `name` → `409` (unique violation mapped to `409`).
- Task `color` is auto-assigned from a unique palette on create when omitted (reuses palette colors once all are in use).
- Unknown resource id → `404` with `{ "error": "..." }`.
- Malformed JSON body → `400`.
- Unexpected errors → `500` with a JSON error body.

Error responses use `{ "error": "<message>" }`.

## Persistence

- PostgreSQL via `pg` (`Pool`). Connection string from `DATABASE_URL` (kept out of git; ignored). Local default: `postgres://postgres@127.0.0.1:5432/taskadmin`.
- Schema applied at startup from `schema.sql` (idempotent `CREATE TABLE IF NOT EXISTS` + seed).
- No `localStorage` writes remain in `app.js`; the browser is a pure API client.

## Frontend Rewire

- `app.js` gains an API client layer (async `fetch` helpers): `listTasks/createTask/updateTask/removeTask` and `listProjects/createProject`.
- `getTasks`/`getProjects` become async fetches; every mutation (add task, edit, delete, drag-and-drop status change, completion checkbox, add project) calls the API and re-renders on success.
- The server owns `createdAt`, defaults `status`, and auto-assigns unique `color`s; the client sends the full task object on updates so unchanged fields are preserved.
- Existing selectors/classes and rendering are preserved so visual behavior is unchanged.

## E2E Testing

- Existing scenarios (taskadmin, kanban, figma-design) and the new API scenarios are served from `specs/tasks-rest-api/tasks-rest-api.feature`.
- `e2e/tests/conftest.py` boots the Express server (instead of `http.server`) against a disposable PostgreSQL database; localStorage seeding helpers switch to API-based seeding.
- Run the API tests with `npm test` and the e2e suite with `e2e/.venv/bin/python -m pytest -v`.
- CI (`ci.yml`) installs Node + PostgreSQL (service container) for the API/e2e jobs.
